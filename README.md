# Assistant Research

Локальный инструмент для исследования обращений к автомобильному голосовому ассистенту. Помогает продуктовой команде определить повторяющиеся потребности, проверить гипотезы о возможных проблемах и перейти от каждого вывода к исходным записям.

Проект выполнен по [TASK.md](assistant-test-20pct-users/TASK.md). Основной пользовательский путь:

**Исследования → карточка → исходный пример → временной контекст.**

## Возможности

- Потоковый импорт JSON с проверкой структуры, SHA-256 и контрольных характеристик.
- Повторный импорт без дубликатов; конфликт содержимого существующего ID отклоняется.
- Две исследовательские карточки: медиапотребности и быстрые повторы сообщений.
- Поиск без учёта регистра, включая кириллицу; фильтры, согласованные счётчики и пагинация.
- Просмотр исходного текста, `actions`, дат, метаданных и полного исходного объекта.
- До пяти предыдущих и пяти следующих записей того же ключа.
- REST API только для чтения и административный интерфейс Django Jazzmin.
- Проверка чувствительности к временному окну и исключению самого активного ключа.

Для работы с подготовленной базой не требуются облачные сервисы или платные API. При первоначальной установке зависимостей нужен доступ к пакетному репозиторию.

## Технологии и окружение

Django отвечает за веб-приложение, ORM, миграции и шаблоны; Django REST Framework — за API; Jazzmin — за оформление админки. SQLite хранит данные и поисковый индекс FTS5. `ijson` используется для потокового импорта. pandas и JupyterLab доступны для дополнительных исследовательских экспериментов; штатная команда анализа использует Python и Django ORM.

Проверенное окружение: **Windows, Python 3.14.6, SQLite 3.50.4**. SQLite должен поддерживать **FTS5 и токенизатор trigram**. Другие версии Python и операционные системы отдельно не проверялись.

В архив включены все имеющиеся записи случайно выбранных **999 из 4 995 ключей**. Это 20% ключей и 18,91% сообщений исходного массива. Единица наблюдения — сообщение или событие истории, а не диалог.

| Контрольный показатель | Значение |
|---|---:|
| Всего записей / различных ID | 260 232 |
| Пользовательские сообщения | 130 934 |
| Ответы ассистента | 129 298 |
| Различные ключи | 999 |
| `deletedAt=null` | 6 875 |
| `deletedAt` заполнен | 253 357 |
| Начало периода | 2024-09-06 09:51:13 |
| Конец периода | 2026-11-04 14:50:41 |

База создаётся в `project/db.sqlite3`. Исходный ID служит первичным ключом. Все 19 полей сохраняются в `source_data`; часто используемые поля дополнительно вынесены в отдельные столбцы. Даты остаются строками исходного формата, поскольку часовой пояс не документирован.

Импорт выполняется пакетами внутри одной транзакции. Ошибка проверки или конфликт ID откатывает записи этой транзакции. Повторяющиеся ID внутри одного файла отклоняются. При повторной загрузке идентичные записи пропускаются, отличающееся содержимое существующего ID вызывает ошибку.

Если рядом с JSON есть `dataset-profile.json`, проверяются хеш файла, роли, число записей и ключей, даты и состояние удаления. В `ImportRun` сохраняются путь, размер, SHA-256, счётчики и длительность последней успешной обработки данного хеша. Это не полный журнал всех запусков.

```powershell
.\venv\Scripts\python.exe project\manage.py import_histories "assistant-test-20pct-users\data\threadhistories_20pct_users.json" --batch-size 1000
```

Допустимый размер пакета — от 1 до 10 000. Фактический размер SQL-вставки дополнительно ограничивается ORM. Повторный запуск на имеющейся базе должен показать `inserted 0`, `unchanged 260232`.

Первый импорт до добавления FTS занял 19,94 с; повторный импорт после оптимизации — 8,34 с. Это измерения конкретного компьютера. Длительность в `ImportRun` исключает финальную фиксацию транзакции и последующее обновление статистики; вывод команды показывает общее время обработки. При последующем аудите на новой временной базе первый импорт с FTS занял 82,79 с, повторный — 11,53 с; повторный запуск добавил 0 записей.

```powershell

.\venv\Scripts\python.exe project\manage.py analyze_histories --active-only
.\venv\Scripts\python.exe project\manage.py analyze_histories --exclude-key 'ТОЧНОЕ_ЗНАЧЕНИЕ_USERSID_HASH'
.\venv\Scripts\python.exe project\manage.py analyze_histories --output "work\analysis-check"
```

`--active-only` означает строго `deletedAt=null`; это не утверждение об активности пользователя. По умолчанию анализируется весь выданный архив. Для разных областей создаются отдельные каталоги; явно заданный `--output` позволяет выбрать место сохранения.

### Правила версии 1.0

**Медиапотребность.** В пользовательском тексте должны одновременно встретиться подстрока из словаря медиатемы и подстрока из словаря команды. Точные выражения находятся в `project/histories/analysis.py` и доступны в карточке. Это лексический отбор: отрицания, грамматика и семантика автоматически не проверяются. Например, «включу музыку» может попасть в подборку без явной команды ассистенту.

**Повторы.** Сравниваются последовательные пользовательские сообщения одного ключа в порядке `created_at, id`. Текст приводится к NFKC и нижнему регистру, пунктуация и символы заменяются пробелами, пробелы схлопываются. Непустые нормализованные строки должны совпасть; интервал — от 0 до 120 секунд включительно. Считается поздняя запись пары. Между попытками могут находиться записи ассистента. Три одинаковых последовательных запроса могут образовать две пары.

| Наблюдение | Сообщения | Ключи | Доля от 130 934 пользовательских сообщений |
|---|---:|---:|---:|
| Медиаправило | 5 430 | 573 | 4,147% |
| Повторы ≤120 с | 1 023 | 318 | 0,781% |
| Повторы ≤60 с | 898 | 297 | 0,686% |
| Повторы ≤30 с | 604 | 222 | 0,461% |

Это частоты совпадений правил в выданном корпусе. Они не являются частотой всех медиапотребностей или ошибок ассистента. В 153 парах нет промежуточной записи ассистента; это не доказывает отсутствия ответа на устройстве.

### Устойчивость и примеры

Самый активный ключ определяется по количеству пользовательских сообщений во всей текущей области, при равенстве — лексикографически. Исключается вся его история. После исключения ключа с 2 422 пользовательскими сообщениями остаются 5 417 медиасовпадений и 1 015 повторов; новый знаменатель — 128 512 пользовательских сообщений.

Выборка для проверки воспроизводится сортировкой SHA-256 от `seed:id`, seed — `20261105`. Для каждой темы и языка (`uz-UZ`, `ru-RU`) выбираются до 15 совпадений и 10 несовпадений. Это выборка сообщений, не независимая выборка людей.

Проверены ИИ: 30 медиасовпадений, 20 медианесовпадений и 30 повторов с контекстом. Для 20 несовпадений повторного правила семантические переформулировки не размечены. Найдены пропущенные узбекские варианты, включая `ashula` и `yutib`. Полнота словаря не измерена.

## Интерфейс и API

### Страницы

| Адрес | Назначение |
|---|---|
| `/` | Карточки и качество данных |
| `/research/media/` | Медиапотребности |
| `/research/repeats/` | Проверка гипотезы о повторах |
| `/records/` | Обозреватель записей |
| `/records/<id>/` | Запись и временной контекст |
| `/admin/` | Админка с авторизацией |

Карточки сохраняют явно обозначенную область полного корпуса. Фильтры обозревателя меняют его выдачу и счётчики, но не выводы карточек.

Контекст берётся из всего архива: до пяти записей до и после текущей записи того же ключа, с сортировкой по времени и ID. Ограничения по длительности промежутка нет. Это **временной контекст, а не подтверждённый диалог**. Исходный текст отображается с экранированием и не выполняется как код или HTML.

### REST API

| Endpoint | Результат GET |
|---|---|
| `/api/records/` | Страница записей, счётчики, область и ссылки пагинации |
| `/api/records/<id>/` | Полная запись, правило контекста, массивы `before` и `after` |
| `/api/research/` | Карточки и сводка качества |
| `/api/research/<slug>/` | Одна карточка (`media` или `repeats`) |

API поддерживает чтение (`GET`, `HEAD`, `OPTIONS`); запись через API не предусмотрена. Размер страницы фиксирован: **50**. Сортировка: `created_at, id`.

| Параметр списка | Формат и смысл |
|---|---|
| `q` | Подстрока до 200 символов, Unicode casefold; без стемминга и транслитерации |
| `id` | Точный неотрицательный ID |
| `start`, `end` | `YYYY-MM-DD`, обе границы включены |
| `role` | `user` или `assistant` |
| `language` | Точная метка, например `uz-UZ`; `__null__` — отсутствующая метка |
| `deleted` | `all` по умолчанию, `null` или `filled` |
| `page` | Номер страницы, начиная с 1 |

Фильтры объединяются через AND. Пустые значения пропускаются. Пример:

```text
/api/records/?q=музыку&role=user&language=ru-RU&deleted=null&page=1
```

Ответ списка содержит `count`, `next`, `previous`, `results`, `scope`, `counts`, `ordering`. `counts` включает записи, различные ключи и количества обеих ролей для всей выбранной области. Превью ограничено 500 символами; `text_truncated` указывает на сокращение. Полный `source_data` доступен в детальном ответе выбранной записи.

Ошибки фильтров возвращают HTTP 400; отсутствующая запись, карточка или страница — 404; неподдерживаемый HTTP-метод — 405. Пустая корректная выборка возвращает 200 и нулевые счётчики.

## Оптимизация

### Изменения

1. **FTS5 trigram.** Для поисковых строк от трёх символов индекс с текстом в casefold выбирает кандидатов; затем применяется точная проверка подстроки. Короткие запросы сохраняют сканирование. MATCH-выражение формируется как экранированная фраза и передаётся параметром.
2. **Индексы.** Добавлены индекс покрытия области и индекс `(created_at, id)` для упорядочивания. После миграции и успешной массовой загрузки обновляется статистика SQLite.
3. **Пагинация.** Счётчик из общего агрегата используется повторно. На глубокой странице сначала выбираются ID, затем загружаются записи. OFFSET по-прежнему имеет линейную стоимость.
4. **Анализ.** Текст нормализуется один раз, повторные проходы для временных окон исключены. При удалении целого ключа переиспользуются совпадения остальных ключей. Выборка использует ограниченную кучу вместо полной сортировки.
5. **Импорт.** При повторной загрузке читаются только ID и исходный объект; даты проверяются ISO-парсером с обратным сравнением формата.

### Замеры

Медиана трёх обращений через Django test client на одной полной базе. Настройка DEBUG не менялась; кеш результатов не используется. Время браузера, сети, холодного запуска и конкурентная нагрузка не измерялись.

|---|---:|---:|
| HTML-обозреватель | 0,3327 | 0,1014 |
| API списка | 0,2481 | 0,1044 |
| Поиск «музыку», роль user | 1,1302 | 0,0627 |
| Страница 4000 | 0,6487 | 0,1007 |
| Фильтр `deletedAt=null` | 0,0257 | 0,0282 |

### Цена и сопровождение

Размер базы вырос с **303,9 до 437,9 МиБ**. Первый импорт с индексом на новой временной базе занял 82,79 с; это единичный замер аудита, а не контролируемое сравнение с прежним импортом. Триггеры автоматически поддерживают FTS при вставке, обновлении и удалении, включая пакетные операции.

Записывать данные следует через настроенные Django-соединения: они регистрируют Unicode-функцию, используемую триггерами. Будущие миграции SQLite с пересозданием таблицы должны сохранять или восстанавливать поисковые триггеры. Индекс управляется миграциями, вручную удалять его не нужно.

## Ограничения и использование ИИ

- `usersid_hash` — наблюдаемый ключ, а не подтверждённый человек или автомобиль.
- В данных нет `session_id`/`thread_id`; временное соседство не устанавливает границы разговоров.
- Ответ «сделано» и код `actions` не доказывают исполнение команды устройством.
- Без аудио и эталонов нельзя измерить точность распознавания речи.
- Единицы временных полей и шкалы существующих меток качества неизвестны.
- Причины заполнения `deletedAt` неизвестны; основной анализ включает эти записи.
- Языковая метка не гарантирует язык текста. Полнота отбора узбекских обращений ограничена словарём.
- Исследование описывает выданную выборку целых ключей; сообщения внутри ключей зависимы.
- Повторы включают благодарности и кодоподобные строки, поэтому их доля не равна доле ошибок.

ИИ использовался для подготовки кода, правил отбора, проверки примеров, тестов, документации и оптимизации. Проверка существенных результатов включала контрольные числа и SHA-256, тесты отката и повторного импорта, просмотр исходных сообщений и контекста, проверку контрпримеров, сравнение наборов ID поиска и побайтовое сравнение результатов анализа после оптимизации.

**Время выполнения проекта:** 3,5 часа (3 часа 30 минут), по данным автора. Заявленное время укладывается в лимит задания — 8 часов. Измерения длительности импорта, анализа и запросов приведены отдельно и не являются общим временем разработки.

Текущие настройки предназначены для локальной демонстрации: используется DEBUG и открытый API чтения. Развёртывание в публичной сети требует отдельной настройки доступа, секретов и эксплуатационного окружения.

## Решение проблем

| Симптом | Действие |
|---|---|
| `No such file or directory` при импорте | Проверить текущую папку. Из корня путь начинается с `assistant-test-20pct-users`, из папки `project` — с `..\assistant-test-20pct-users` |
| Не найдены таблицы истории или FTS | Выполнить `project\manage.py migrate` из корня |
| `no such module: fts5` / нет `trigram` | Использовать сборку Python/SQLite с требуемой поддержкой; выполнить проверку из раздела установки |
| Ошибка `history_casefold` при прямой записи SQLite | Выполнять запись через Django и команду импорта |
| Несовпадение SHA-256 | Проверить, что JSON и профиль относятся к одному неизменённому архиву |
| Конфликт существующего ID | Проверить источник: команда защищает уже сохранённое содержимое от перезаписи |
| Не найдены артефакты исследований | Выполнить анализ; восстановить `research/cards.json` из исходников, поскольку он не генерируется автоматически |
| `database is locked` | Дождаться завершения другой операции записи, закрыть внешние редакторы базы и повторить команду |
| Порт 8000 занят | Использовать уже работающий сервер либо `runserver 127.0.0.1:8001` |
| Поиск из одного-двух символов медленный | Уточнить текст или добавить фильтры: короткие подстроки не используют trigram-индекс |
