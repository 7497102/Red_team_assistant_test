# Исследование истории ассистента

## Воспроизведение

Из папки `TZ project/project`, с активированным окружением:

```powershell
python manage.py analyze_histories
python manage.py analyze_histories --active-only
python manage.py analyze_histories --exclude-key 'ТОЧНЫЙ_КЛЮЧ'
python manage.py test histories
```

Из корня проекта используйте `.\venv\Scripts\python.exe project\manage.py ...`.
Результаты полного корпуса записываются в `research/generated/`; активный архив
и исключение ключа получают отдельные каталоги. `--output` задаёт каталог явно.
Повторный запуск заменяет вычисленные файлы, но не `reviewed_examples.csv` и `cards.json`.
Карточки и интерпретации зафиксированы для версии 1.0 и полного корпуса.
После изменения правил или данных их следует перепроверить.

## Область и методы

Весь предоставленный корпус, включая заполненный deletedAt: 260232 записи,
130934 пользовательских сообщения, 999 наблюдаемых ключей. Период:
2024-09-06 09:51:13 — 2026-11-04 14:50:41, часовой пояс неизвестен.
Один ключ не обязательно соответствует человеку или автомобилю.
Доли сообщений относятся к этому корпусу, не ко всей исходной популяции.

Точные регулярные выражения и нормализация находятся в `histories/analysis.py`.
Медиаправило требует одновременно подстроку из словаря темы и подстроку из
словаря команды в пользовательском тексте, без учёта регистра. Это экран отбора:
он допускает ложные совпадения («включу музыку») и пропуски (ashula, yutib).
Порядок слов, грамматика, отрицания и семантика автоматически не проверяются.

Повтор: сравниваются последовательные пользовательские записи одного ключа
в порядке created_at, id. NFKC, нижний регистр, замена знаков пунктуации и символов
пробелами, схлопывание пробелов. Непустые нормализованные строки должны совпасть,
разница времени — от 0 до 120 секунд включительно. Единица — поздняя запись пары;
цепочка из трёх повторов даёт две пары. Это не подтверждённые диалоги.
Промежуточные ответы сохраняются как временной контекст, без доказанного соответствия.
В вариантах с фильтрами последовательность строится внутри выбранной области.

Знаменатель доли для обеих тем — все пользовательские сообщения области,
а для охвата ключей — все ключи с пользовательскими сообщениями.
Это описательные доли совпадений, а не вероятность ошибки или успешности.

Самый активный ключ определяется по числу пользовательских сообщений во всей

репрезентативность. Полный ключ и пересчитанные знаменатели — в analysis.json.

## Качество и язык

2463 текста пусты; 336 записей не имеют языковой метки. Топ-10 ключей дают
10.931% пользовательских сообщений. Групповые зависимости существенны.
Среди пользовательских сообщений 90937 имеют метку uz-UZ, 39068 — ru-RU.
Медиаправило находит 2149 узбекских и 3269 русских сообщений. Разницу нельзя
интерпретировать как разницу потребностей: охват словаря и качество текста различаются.
Ноябрь 2026 неполный; месячные числа нельзя автоматически читать как рост продукта.
Пустой actions, качество речи, коды исполнения и временные поля не интерпретируются
как документированные технические метрики.

## Проверка примеров и карточки

`review_candidates.csv`: для каждой темы по 15 совпадений и 10 несовпадений
на каждый из языков uz-UZ и ru-RU. Отбор по сортировке SHA256(seed:id), seed=20261105.
Это выборка сообщений, не ключей; она не предназначена для оценки всей популяции.
`review_context.json` сохраняет предыдущую попытку и промежуточные ответы для
выбранных повторов. `media_matches.json` и `repeats_matches.json` сохраняют все
совпадения с исходными ID. `user_activity.json` содержит активность каждого ключа.

Проверка выполнена ИИ-ассистентом по исходным текстам, а не независимым экспертом:
30 медиасовпадений, 20 медианесовпадений и 30 повторов с временным контекстом.
Для остальных 20 несовпадений повторного правила просмотрен текст, но не размечены
семантические переформулировки; это явно отмечено в reviewed_examples.csv.
Из 30 медиасовпадений 24 поддерживают потребность, 6 неоднозначны. Эти числа нельзя
выдавать за точность на корпусе. Лингвистическая оценка требует проверки носителем языка.

Целевой поиск выявил пропуски: 4655, 24097, 27938, 60274. Правило их не учитывает;
точный способ поиска и комментарии сохранены в coverage_misses.json.
Небольшая случайная подборка не оценивает recall; значительная доля потребности
может быть пропущена, особенно в узбекских вариантах написания.

`cards.json` содержит две карточки с областью расчёта, числами, пятью примерами,
контрпримером и экспериментом. Веб-интерфейс и API формируют ссылки `/records/<id>/`, доступные без авторизации. На странице записи показаны исходные поля и временной контекст. Сохранённые в JSON ссылки на Django admin заменяются при загрузке карточек приложением.

Медиапотребность подтверждают примеры просьб открыть сервис или воспроизвести
конкретный контент. Пример 233050 («включу музыку») ослабляет точность отбора.
Следующий эксперимент — сценарий с сервисом и названием контента, одним уточнением
при неоднозначности и наблюдаемым завершением задания.

Повтор как доказательство ошибки не подтверждён: 667989 следует за пустым ответом,
413422 — за сообщением об отсутствии команды, но 457699 следует за прямым ответом,
а 130993 — повторная благодарность. Коды и подтверждения не доказывают исполнение.
Следующий эксперимент — сопоставить повторы с телеметрией выполнения и наблюдением
за пользователем, отдельно проверить пустые ответы и неподдерживаемые команды.
